We are Group 0. This is the Phase 6 progress update for Workload-Aware Calendar, a Chrome extension on Google Calendar. We will cover progress to date, the interface snapshots, how the design evolved, and why we diverged from the Phase 5 plan. Questions fit inside the six minutes.

Rubric

Progress, interface snapshots, design evolution, divergence, and a talk a reviewer can follow without being in the room.

The goal is unchanged. Show estimated effort beside the deadline, mark a heavy day, and start larger work earlier. Assignments come in, WAC holds the plan, and the student can change it before it hits the calendar.

Rubric

Progress to date, measured against the original plan.

Accessibility is part of the design. Plus signs and stripes say low, medium, or high, and the course color stays the course, so effort is never color alone. Early blocks and a reminder count leave time that is not packed with classwork.

Rubric

Accessible. The requirement is written on the slide, not only spoken.

The event design evolved to tags and stripes. We set aside colored borders because they clash with the course color and fail when someone cannot use color.

Rubric

Design evolution, and the rationale for that divergence.

We set aside the full-day heatmap because it crowds out free time. We kept a mark for colliding deadlines, and we place work in earlier open time instead of on the due day.

Rubric

Design evolution, and why that earlier plan was dropped.

The clock fill and the pointed pill were earlier ideas, and we did not ship them. Shape is easy to miss, and it does not carry effort for a color-blind reader. The build uses the tag and the stripe.

Rubric

Divergence from previous design plans, with the reason.

This snapshot is the running side panel on Google Calendar, the week of November 15. It flags a busy Monday, December 7, two deadlines and about six hours, and it points Find time at earlier open days. Literature review is on the list, with the plus buttons.

Rubric

Progress to date, shown as an interface snapshot.

This second snapshot is Work blocks beside that same week. Course events keep their color. The WAC blocks are striped, and the list can be published. The busy note is Thursday, December 10, about five hours.

Rubric

Interface snapshot. Say what is on the screen so the slide stands alone.

Preferences set the block length, the hours per day, and the reminder count. Tags and stripes show the tier, the course color still means the course, and one click changes it. The close-up reads three plus, High, on a stripe. Blocks sit on the mini calendar in the panel.

Rubric

Progress, a snapshot, and effort that is not color alone.

We diverged from the Phase 5 plan for three reasons. No live Canvas, because students cannot use that API, so details are typed or taken from the PDF. Not in the Chrome Web Store, because this is a study interface, not a product. Stripes are on the website only, not in the phone app.

Rubric

Rationale for divergence from the previous design.

Still open: clearer marks, a simpler flow, and the user study. The study has not been run. The task breakdown is updated for who owns the remaining work, and that document is the other ten percent of this phase.

Rubric

Honest progress, plus the updated task breakdown.

This is the study plan, not a result. Ask how they handle deadlines now, show the extension, then watch them use it and compare ease and mental load. No participants yet. That is the update.

Rubric

Do not claim the evaluation is finished. It is the next phase.
